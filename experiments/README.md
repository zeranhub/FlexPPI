所有入口默认只列出步骤；`--help`、`--list` 和 `--check` 均不导入科学软件，也不进行训练、预测、MD 或统计复算。只有显式指定 `--step` 才会调用原程序。`--check` 仅检查登记的脚本和少量关键本地输入是否存在，不能替代科学环境、外部轨迹、GPU及冻结哈希的完整检查。原程序的参数放在分隔符 `--` 后面原样转交，也可通过 `--python` 指定对应科学环境中的解释器，例如：

```powershell
python "experiments/3_1_两类动态预测与完整结构环境的贡献.py" --list
python "experiments/3_2_同类型残基的局部动态差异.py" --check
python "experiments/3_2_同类型残基的局部动态差异.py" --step within_type_mae -- --help
python "experiments/C_基线实现与来源比较.py" --step score_common -- --help
```

实际执行仍使用原程序的工作流程和参数。部分原程序没有参数解析，指定相应 `--step` 就会开始计算；应先看 `--list` 中的说明。3.2 的 `within_type_mae` 是轻量适配入口，它直接复用留存生产程序的 `sidechain_rows` 函数，保留身份、共同掩码、样本数量和配对位置检查，要求显式提供新的 `--output` 目录，不训练、不推理，也不重新绘制历史图。其余原始生产代码及原始宏表同时保留，便于对照。

`_sources/` 是原 `paper/revision_v14_20261010/experiment_completion/` 的科学实现及数值产物，内部相对布局继续保留；名称中的版本号可用于追溯原始统计来源。`core_corrected_pipeline/` 从 `C:/Users/DELL/.codex/worktrees/4666/FlexPPI/paper/revision_20261002/experiments/corrected_pipeline/` 收拢了这一版真正使用的校正训练载荷、源代码、五折 OOF 预测、静态对照、保存的第 40 轮权重及训练记录。`PRESERVATION_MANIFEST.json` 记录主体 13,122 个文件、1,768,714,889 字节的原始与复制后 SHA256，源 C 盘工作树未改动。少量辅助脚本之后做了导入和路径迁移，当前脚本哈希另记在 `RELOCATION_CHANGES.json`，不能把复制时的哈希当成迁移后脚本的哈希。冻结训练载荷的代码、配置、清单、模型及数值数组没有因此改写。`type_analysis/SOURCE_MANIFEST.json` 另记录类型内 MAE 生产函数、原始统计表、对齐基线数组及其依赖，并区分原始和迁移后脚本哈希；`reproducibility/SOURCE_MANIFEST.json` 记录原标签构建所需的补充源码和配置。OOF 意为每条记录由没有拿它训练的那一折模型产生的预测，不能用根 `scripts/` 中较早的 3,068 条记录导出器替代本目录的 3,063 条记录结果。

`_case_validation_sources/` 保存 KIX 和泛素结构个案的真实轨迹来源、残基表与可编辑结构会话；`_legacy_paper_data/` 保存旧论文中仍需留存的数值资料。最终论文六套图及各自可编辑源文件统一在 `paper/figures_v58/`，本目录不再把旧绘图迭代当作最终图。主文 KIX 仅使用四种组成各一条既有轨迹；保留的 MD 程序能够启动更多重复，但更多重复不等于本版论文新增的实验结果。

本次整理未重跑训练、预测、模拟或科学统计。完整重跑仍需原始 ATLAS、DynaRepo、ITrace 和 ThermoPCD 轨迹，以及各基线的软件与权重。保存的训练清单继续保留原 Linux 数据路径和冻结哈希；在新机器重训或重新导出时，应通过配置中的 `path_mappings` 或在原部署布局下运行，不应直接改写冻结清单的内容。原训练/家族评价程序默认使用 CUDA，训练检查点在 `core_corrected_pipeline/trained_checkpoints/`，部分历史部署程序要求将其映射到相应运行根下的 `runs/`。原始轨迹与先前审核使用的临时规范化拓扑未全部内嵌在这些入口中；局部 MD 重提取若缺原始文件或临时副本，会按原程序的身份及哈希检查报错，已有最终曲线和数值源表仍可用于查看与绘图。
